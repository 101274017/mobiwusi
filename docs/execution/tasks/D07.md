## 双状态与执行边界

- `development_status` 仅表示当前自动开发预检层；实际范围以所列命令报告、版本和文件指纹为准，不声明全部 WBS 工作包已完成。
- 本地调度读取前置任务的 `development` 并遵守原 FS/SS/FF；不存在“全部外部验收 accepted 后才能编码”的全局门。
- `status=blocked`、`acceptance=preparatory_not_accepted` 和 `execution_started=false` 保留为正式验收字段；并非本地代码工作未发生。
- 真实平台权限、用户同意、供应凭证和正式发布证据不能由自动开发决定代替；缺项保留为 `verification=external_pending`。
- 真实编译、契约、隔离、停止或失效证据错误属于 `DEV_BLOCKED`，不能改名为外部待项。

## 实施内容

复用统一判定函数，自动生成并校验d07-decision.json，输出开发/发布双结果；交付：自动报告/工程交接/能力账本

## 原任务验收范围

开发检查通过即可DEV_READY或DEV_READY_WITH_EXTERNAL_PENDING；无需人工决策文件或签字

## 风险边界

实际相关软件失败须修；external_pending只限制相应真实验证/生产，不全局阻断代码

## 可复现入口

```powershell
pnpm d07:decision:check
pnpm d07:release:check
```

前者默认计算开发门禁；后者在外部证据不足时必须非 0 且 `release.ready=false`。本卡不要求用户提供签字、Top20、角色或手填开发决策 JSON。
