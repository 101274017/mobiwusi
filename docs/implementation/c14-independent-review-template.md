# C14 独立契约评审记录（D02 手工评审模板）

> **状态：草案 / 未完成。** 本文件是可填写的独立评审模板，不是已完成的评审报告、契约冻结记录、后端上线证明或 D02 批准。填写、签名或保存本模板本身不会自动冻结契约，也不会启动 E/F；E/F 仍须在正式 D Go/No-Go 批准后按项目实施计划进入。

## 0. 使用规则

- 评审者逐条核对“评审对象”的源定义、生成物和可复核证据；不能以自动审计通过、Mock 运行或文档存在代替独立判断。
- 每条结论只能使用：`通过`、`有条件通过`、`不通过`、`未评审`。`不适用`必须写明理由，并由评审者确认不影响 D02。
- 证据引用应至少能定位到文件/记录、版本或哈希、相关操作或事件；不得填入真实密码、令牌、私钥、原始媒体或其他秘密。
- 评审范围发生变更时，重新填写版本/提交/哈希范围，并说明新增、删除和重新评审的条目。

| PRO-01 | 契约源定义是唯一来源；OpenAPI、JSON Schema、TypeScript DTO、Kotlin DTO 和 fixture 可由同一快照追溯，生成文件未被直接改写。 |  |  |  |

### 3.3 错误包络与失败语义（ERR）

| --- | --- | --- | --- | --- |
| ERR-01 | 成功统一为 `{data, request_id, schema_version}`；失败统一为 `{error:{code,message,retryable,details},request_id}`，字段可由 Schema 校验。 |  |  |  |
| ERR-02 | `AUTH_EXPIRED`、`SCOPE_DENIED`、`CONSENT_REQUIRED`、`PERMISSION_DENIED`、`RISK_PAUSED`、`TARGET_STALE`、`LOW_CONFIDENCE`、`VERSION_CONFLICT`、`RATE_LIMITED`、`PROVIDER_UNAVAILABLE`、`CANCELLED` 等边界有明确映射。 |  |  |  |
| ERR-03 | 每类失败的 `retryable`、重试窗口、退避、取消和人工/电话替代路径明确；不能把超时或取消写成业务成功。 |  |  |  |
| ERR-04 | 409 冲突、429 限流、认证过期、供应不可用、权限拒绝、风险暂停和目标过期不会静默降级为 Mock 或成功响应。 |  |  |  |
| ERR-05 | 错误消息可向用户安全解释；details 不泄露秘密、内部堆栈、供应商敏感信息或不可授权对象内容。 |  |  |  |
