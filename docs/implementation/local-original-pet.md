# 本机原画直接设为独立桌宠

## 使用流程

1. 从桌宠右键菜单或管理窗口进入“画一画”。
2. 绘画后点击“保存本机草稿”，原始笔画保存到当前本机绘画资料。
3. 点击“预览原画桌宠”，查看透明背景、去除四周空白后的原画。修改后须重新保存再预览。
4. 亲手点击“直接设为桌宠”，独立悬浮窗口即时切换到这张原画。仅保存或预览不会替换当前桌宠。

无需生成服务、登录或 AI 调用；不会上传原画，也不会改画或伪造骨骼动画。原画形象继续使用原有桌宠按钮、拖动区域、右键菜单和问答面板。

## 保存与恢复

- 画稿继续保存在原来的 IndexedDB 绘画仓储，按当前资料命名空间隔离。
- 经确认应用的形象单独保存为 Electron `userData` 目录内固定的 `nuanban-original-pet.png`。
- 关闭管理窗口后独立桌宠继续运行；重启后从本机图片恢复已应用的形象。
- “恢复内置桌宠”只删除已应用图片，保留原始画稿，可以再次预览并应用。清画布不会删除已应用形象。
- 设置页的清空本机资料与画稿操作同时恢复内置形象。
- 浏览器可以保存和预览，但不能冒充已替换系统桌宠；应用按钮会明确禁用。

## 失败与边界

- 空白或全部擦除的画作不能应用；应用失败保留预览与画稿，显示错误并允许重试。
- 主进程只接受本机预览生成的 PNG 数据，限制为 2 MiB、800 × 480 像素；拒绝 URL、SVG、任意文件路径及全透明图。
- 只有受信任的管理主框架能写入或恢复；桌宠主框架只能读取和接收变更通知。
- 图片持久化优先使用同目录临时文件重命名。若本机资料目录返回 `EXDEV`，改为保留 `.previous` 恢复副本后复制，落盘并比对完整图片后才移除副本、提交新形象；失败或中断时从恢复副本读取旧形象，首次应用失败则仍为内置形象。损坏文件不会被报告为应用成功。
- 恢复副本未提交时不会被后续应用覆盖；再次应用可重试，恢复内置会一并清除未提交图片和恢复副本，不影响 IndexedDB 原始画稿。
- 沙箱、上下文隔离、页面来源校验和 CSP 保持开启。仅图片增加 `data:` 来源，不允许 `unsafe-eval`。
- 未使用远端契约校验器时不提前初始化 AJV，避免本机绘画启动触发 CSP 禁止的动态编译；这不代表远端服务已完成严格 CSP 兼容验收。

## 构建与复现

在仓库根目录运行：

```powershell
pnpm build
pnpm desktop:artwork:check
pnpm exec vitest run tests/platform/desktop-local-artwork.test.ts tests/contract/lazy-validation.test.ts tests/contract/services.test.ts
$env:PLAYWRIGHT_CHANNEL='msedge'
pnpm exec playwright test tests/e2e/local-artwork.spec.ts --workers=1
```

真实 Electron 检查使用随机临时应用副本、独立 `userData` 和 `sessionData`，不改用户画稿，不关闭已运行的客户端，不开启屏幕观察或麦克风。检查保存、透明预览、确认后切换、原有面板、关闭管理窗口、重启持久化及恢复内置，完成后只清理自己的临时目录。设置 `NUANBAN_ARTWORK_SCREENSHOT_DIR` 可额外保存预览和悬浮窗口截图。

若要复现特定资料目录的文件系统行为，可将 `NUANBAN_ARTWORK_PROFILE_PARENT` 设为该目录。检查只在其下创建随机 `nuanban-artwork-profile-check-` 子目录，不使用父目录现有数据库或图片；同时检查首次应用、再次替换与重启恢复，最后仅清理该随机子目录。故障单测另覆盖 `EXDEV`、复制中途空间不足、恢复副本写入失败和提交失败，确认失败不冒充成功、不复活未提交图片。

开发客户端优先读取最新 `apps/web/dist`；打包客户端读取包内 `ui`。已打开的旧客户端需要在方便时正常退出再启动，源代码修改不会自动更新旧进程。开发运行与自动化检查不替代完整安装包、签名、混合 DPI 或生产验收。
