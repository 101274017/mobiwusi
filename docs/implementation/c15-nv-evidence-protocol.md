更新日期：2026-10-17（Asia/Shanghai）。本文件对应实施计划 C15「NV 实测与安全副作用复核」。当前只建立证据准入审计和记录格式；没有设备、供应凭证或独立复核时，逐项状态必须是 `blocked`，不能填写通过。

## 状态语义

- `blocked`：必要设备、供应、权限、计数或独立复核缺失；不能进入 D。
- `ready_for_independent_review`：记录字段齐全且候选证据已形成，只能交给独立复核，不代表 NV 通过。
- `passed`：只有完成计划要求的真实设备/供应操作、计数和独立复核后才允许使用；当前审计器不会直接产生此状态。

运行：

```powershell
pnpm c15:nv:check
```

结果写入 `docs/implementation/evidence/c15-nv-readiness-results.json`。该文件是准入审计报告，不是设备或供应验收报告。

## 证据质量与缺口追踪

- 审计为每个引用文件记录 `sourcePath`、字节数和本次读取的 `contentSha256`，并检查声明的 `generatedAt`、时区、来源描述和限制字段。内容哈希只锁定被审计的文件版本，不把合成文件变成真实设备/供应证据。
- `auditPassed:true` 仅表示引用文件存在且可解析；`evidenceQualityPassed` 另行表示时间/来源/限制等最小元数据是否齐全。二者都不能替代真实设备、真实供应或独立复核。
- 每项 NV 的 `failedSignals` 列出未满足的文件路径和值，`blockerRefs` 以稳定代码关联失败信号或证据元数据缺口；`blockers` 仍保留人类可读的阻塞原因。这样不能只看一个总状态而丢失具体补证动作。
- 当前引用的上游证据已补齐日期时区、来源描述和限制字段，`evidenceQualityPassed=true`；这只表示证据元数据可追踪，不表示设备、供应或独立复核信号满足准入。
- 只读检查可运行 `node scripts/check-c15-nv-readiness.mjs --no-write`；写入报告的命令仍为 `pnpm c15:nv:check`。

## 统一记录字段

每条真实记录必须包含：日期和时区、构建/包哈希、设备型号/系统/DPI、用例与合成素材哈希、前置权限和当次同意、操作步骤/预期/实际、帧/编码/发送/接收/缓存计数、截图或视频引用、限制、执行者和独立复核者。不能写入真实密码、验证码、银行卡、私人聊天或儿童原始素材。

## 当前结论

`pnpm c15:nv:check` 当前文件可解析性和证据质量审计均通过，但 NV-01～NV-12 全部仍为 `blocked`，`goNoGoEligible=false`。合成单测、契约审查、打包、单屏几何或本地内存 relay 不能替代 C15 的真实设备/供应证据；在逐项记录和独立复核完成前，不得通过 D 或启动真实 E/F。
