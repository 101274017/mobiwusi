## 3. 两套独立门禁，消除D07全局死锁

### 3.1 开发门禁：允许Codex继续工程工作

以下为D07应自动检查的开发条件：

1. 当前已有前端能在项目提供的开发方式下启动；关键交互/确定性Mock与错误路径有可执行检查。
2. 当前公共契约和事件Schema可校验，C14版本/兼容规则明确，已实现部分的消费者检查通过。
3. C17组合根与平台端口有实际代码；apiMode/platformMode独立；不能由模拟状态伪造系统授权。
4. 数据发送门控、停止、敏感/未知页保护等已有实现的安全检查通过；未验证的外发能力默认关闭，关闭状态和拒绝路径也必须有测试。
5. 本轮改动可检查，无未处理的相关编译/契约/安全错误；证据关联实际版本与工作树。
6. 所有不可执行的外部验证均有明确条目、受影响能力和关闭策略，不用假通过替代。

不把人工签名、真人监护证明、供应商生产凭证、所有真机证据、真实试点或“独立人类复核者”设为继续写代码的前置。自动复核检查命令、证据来源和反例，记录review_type=automated，不要求组建虚构人员。

### 3.2 开发结果与后续动作

| development.verdict | 计算条件 | 动作 |
| --- | --- | --- |
| DEV_READY | 相关开发检查通过，当前范围无外部待项 | 保存决定，继续依赖满足的E阶段实现 |
| DEV_READY_WITH_EXTERNAL_PENDING | 开发检查通过；存在真实设备/供应/试点等外部待项；受影响能力未被误启用 | 保存待项与关闭证据，继续E阶段代码、本地服务和自动化验证 |
| DEV_BLOCKED | 实际可执行的相关检查失败、契约不一致、危险外发未隔离、证据失效或状态工具链错误 | 自动修复并重验；独立且不依赖该缺陷的工作可继续，不能伪造通过 |

DEV_BLOCKED表示真实软件问题，不是“未提供人工材料”的同义词。同一输入指纹没有变化时，不无限循环同一条检查。Codex应定位并修复代码或检查器，再生成新证据。确实无法修复的缺陷保留失败与下一动作，不能为了让流程继续将失败改成external_pending。

### 3.3 发布门禁：不会被开发通过自动解锁

release.verdict单独记录NOT_ASSESSED、EXTERNAL_PENDING、BLOCKED或READY。正式对外能力开放须有相应真实证明、有效授权和目标支持矩阵；真实支付/敏感场景保护等要求不降低。

DEV_READY_WITH_EXTERNAL_PENDING不等于release READY，也不意味着96项任务已完成全部真实验收。外部条件未知时release.ready必须为false。允许先完成后端真实业务逻辑、数据库、对象鉴权、任务与本地集成，不允许借此把未验证的媒体/采集路径向真实用户开放。

**依赖解释更新：** 原FS/SS/FF继续约束代码间的前后关系；开发调度读取前置任务的development状态。原任务涉及外部实测/签收的要求留在verification/external状态中，不再要求其全部变成accepted才能开始下游编码。发布调度则检查对应真实验证，不使用开发状态代替。D07这项流程变更须同步到旧任务卡和项目指令，不能让新旧规则同时生效。

## 4. 必须先修的检查器与命令链

### 4.1 修复顺序

1. 有界读取package.json、相关脚本/Schema/测试、RUN与当前证据目录，查找固定draft/blocked、人工字段及C17冲突。
2. 把流程判定抽成一个共享纯函数，例如evaluateProjectGate(context, evidence)。名称可随现有结构，不能为每个脚本再复制一套规则。
3. 修C14：读取真实契约版本、校验与消费者结果，自动冻结/更新版本清单；无人签名不影响开发技术冻结。破坏性契约错误仍失败。
4. 修C17：对当前组合根、存储/平台桥契约、可用宿主集成执行检查；native外部项与local结果分开，不固定返回blocked。
5. 修C15/C16：合并自动测试证据、默认决策与外部台账，不以真人签字生成“独立复核已完成”。
6. 修验收包：开发模式和D07复用相同输入/函数/枚举，禁止一处要求C17阻断、一处要求它就绪。
7. 修D07：自动生成、Schema校验、必要时更新开发决策文件；生成过程幂等，不覆盖用户自有证据/历史签收。
8. 增加关键回归，执行开发验证，得到真实结果后立即推进E07和其他可编码项。

旧测试若专门断言某脚本永久blocked，应改成有输入条件的正反用例；不能删掉所有失败用例或把检查改为无条件退出0。脚本状态来自真实证据，不来自为了过关临时写入的假结果。

保留截图里已有命令名，具体脚本参数在实际仓库实现后确定。下表是待实施的接口约定，不代表本次已经运行过。

| 命令用途 | 所需行为 |
| --- | --- |
| pnpm d07:decision:check | 默认检查开发门禁；决定文件缺失时根据实际证据自动生成再校验。开发通过可退出0；失败输出具体本地错误 |

| 平台/设备范围 | 自动识别当前OS/工具链；先完成Windows与Android工程和可运行测试 | 未测设备不标支持；不可运行目标加入外部验证 |
