# C01 Android 独立原生验证样例

日期：2026-10-15。对应实施计划 C01 / NV-01、NV-02 的**预备代码**，不是验收完成项。原始三份文档保持不变；D 未批准，E/F 不启动。

## 隔离与默认行为

- 独立应用 ID `org.nuanban.nativelab`，名称「暖伴 · C01 验证」。与正常演示包 `org.nuanban.assistant` 不共享权限、仓储或 WebView 桥。
- 普通 `pnpm android:build -Offline` 只构建 `:app`；独立包必须显式执行下面的 lab 命令。本仓库没有自动安装、自动启动或自动点击系统授权的脚本。
- 进入页面不申请采集。勾选本次合成内容说明、通知可用、点击开始并通过本次系统屏幕授权后，才尝试启动前台服务。通知拒绝/关闭时不开始；授权失败后不自动重试。
- 浮层为独立可选项，先由用户到系统设置授权，再另行开始实验。只绘制固定半透明穿透标记和可点击停止按钮，不自动操作底层应用，不将它当作定位指引。
- 清单无 `INTERNET`、相机、麦克风权限。样例不访问帧像素、不生成预览、不编码、不落盘、不上传，也不把帧交给页面或外部组件。这里不是 C03 检测/脱敏模型，所有内容均未被判安全。
- 没有账号、AI、亲情媒体、供应凭证或真实业务后端；共享前端所有高风险能力保持 false。不能据此把 C17 视为真实捕获已装配。

## 构建与本机检查

在项目根目录运行：

```powershell
pnpm android:lab:check
pnpm android:lab:build -Offline
$env:JAVA_HOME = 'C:/Program Files/Android/Android Studio/jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA/Android/Sdk"
apps/android/gradlew.bat -p apps/android :native-lab:lintDebug --offline --no-daemon
pnpm android:lab:evidence
```

依赖、SDK/JDK 与正常 Android 工程相同，`-Offline` 只使用已有缓存；首次没有依赖缓存时不要把缺依赖误判为功能测试失败。构建脚本也支持 `-SdkRoot`、`-JavaHome`。

输出 `apps/android/native-lab/build/outputs/apk/debug/native-lab-debug.apk`，仅为本机调试签名包。正常演示 APK 路径不变。

证据命令要求成功的构建/Lint 日志保存在 `docs/implementation/evidence/android-lab-build.txt`、`android-lab-lint.txt`；可用 `2>&1 | Tee-Object -FilePath <路径>` 保存上述命令。它校验源码未晚于 APK、JVM 源哈希、最终 APK 权限/DEX 类/无 Web UI，再记录产物和源码哈希。仅枚举 ADB 设备数量，不安装或启动，也不把结果写成设备通过。

`android:lab:check` 使用缓存 Kotlin 2.2.20/JVM 17 编译真实 `LabSession.kt` 和 `ReminderPolicy.kt`，覆盖 35 个捕获状态机用例与 10 个 Android 提醒权限/能力矩阵场景；5 个 Vitest 用例检查独立清单、正常应用权限未变化、无像素/外发入口、停止顺序和提醒策略不调用系统 API。编译、静态测试、JVM 测试和 Lint 均**不能代替实际 WebView、系统权限、Room、后台调度或设备验证**。当前未连接 ADB 设备，没有执行安装或采集。

`ReminderPolicy.kt` 只根据注入的 API、通知开关、通知渠道、精确闹钟和后台调度状态计算 `system`、`page_only` 或 `unsupported`；它不调用 `NotificationManager`、`AlarmManager` 或 `WorkManager`，因此不能证明 Android 系统提醒已接入。

## 生命周期和资源边界

1. 每次授权由 nonce + generation 绑定；拒绝、停止或旧授权回调不能开启新会话，同一系统授权结果只消费一次。
2. 前台服务先请求显示停止通知，再注册投影回调、建立虚拟屏和 `ImageReader`。实际通知可见性仍待设备确认。缓冲数为 2，按短边不超过 720、长边不超过 1280 缩小；计数只是 `acquireLatestImage` 取出的帧，不能表示系统产生的全部帧。
3. 取出的帧只调用 `close`。旧代际帧同样释放，不能转成可发送数据；释放异常关闭当前代际。
4. 用户按钮、浮层按钮、通知停止、系统撤销、锁屏/熄屏、显示变化、任务移除和服务销毁均走先 fence、再释放路径。任何默认显示器变化都保守停止，可能误停，待设备验证。
5. 设置 30 秒停止计时，处理帧前还会用单调时钟复查到期。系统调度/主线程阻塞会影响实际资源释放时间，**不承诺精确 30 秒已完成 OS 清理**；必须实测停止延迟和系统状态。
6. 关闭监听、虚拟屏、帧缓冲和投影，移除浮层并停前台服务。待清理期间禁止新授权；清理异常时显示未确认并禁止本进程再次开始，须由系统停止投影并结束进程。
7. 服务为 `START_NOT_STICKY`，授权结果不持久化，没有自启动/重启恢复。清空/杀进程后历史计数丢失是设计行为，不伪装已恢复会话。

屏幕可能仍含隐私，系统权限不等于用途或安全结论。仅允许使用本机合成 canary 和受控的合成测试应用；不要打开真实聊天、支付、账号或验证码内容。此样例不具备检测器，不能用于面向真实用户的教学/共享。
